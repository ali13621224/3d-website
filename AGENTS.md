# AGENTS.md

## Running in the Base44 sandbox

Use `docker-compose.base44.yml` — not any other compose file:

```sh
docker compose -f docker-compose.base44.yml up -d --build
```

Non-obvious things worth knowing:

- **No secrets are required.** The app is entirely client-side: React, Vite and
  React Three Fiber (WebGL). There is no backend, database or third-party API, so
  there is nothing to put in `/run/base44/app.env`.
- **Dependencies are installed at container start**, into the `node_modules`
  named volume (never the repo). The first boot therefore takes ~1 minute; the
  healthcheck has a 120s `start_period` to cover it.
- **`package-lock.json` is generated by that first install** and should be
  committed so later installs are reproducible.
- **The dev server must stay a dev server.** `vite` serves the source over port
  3000; a production build (`dist/`) would break the edit-in-place loop.
- **Sandbox host/origin overrides are gated on `BASE44_PREVIEW_MODE === "1"`**
  in `vite.config.js`: `allowedHosts` gains `.<BASE44_SANDBOX_HOST_DOMAIN>` (the
  sandbox id rotates, so the wildcard is required) and HMR is pinned to
  `wss` on port 443 because the preview proxy terminates TLS. With the variable
  unset, plain `npm run dev` behaves exactly as stock Vite.

## Verifying it works

1. `docker compose -f docker-compose.base44.yml ps` → `web` is `healthy`.
2. `curl -s http://localhost:3000/ | grep root` returns the Vite-served HTML.
3. The page renders a dark hero ("Shape light, move matter.") with a WebGL orb;
   the WebGL canvas is live geometry, so it should react to the cursor and to
   scrolling. Console must be free of WebGL/context errors.

## Notes for future changes

- The 3D scene lives in `src/components/Scene3D.jsx`; the page sections are
  sibling components under `src/components/`. Global styling is `src/index.css`
  (no CSS framework).
- Avoid drei helpers that fetch remote assets (`Environment` presets, `Text`
  with a remote font) — the sandbox preview should stay offline-safe.
